**Status and evidence contract**

- COMPLETE: the narrowly stated requirement passed suitable current validation. A static
  navigation entry can be COMPLETE while its browser/auth/business behavior is UNVERIFIED.
- PARTIAL: a concrete portion is evidenced and the named remainder is unfinished.
- NOT STARTED: no execution evidence for the specific planned task; never infer absent code.
- BLOCKED: an identified environment/decision/acceptance dependency prevents completion.
- FAILED: a validation run failed; preserve exact cause and distinguish user/pre-existing work.
- UNVERIFIED: source/docs/history exist but sufficient current acceptance evidence is absent.
- NOT APPLICABLE: not an approved requirement for this page/task; not a missing feature.

E = verified in this audit; H = historical evidence only; S = source inspection only;
D = approved documentation/decision; NT = not tested. Dates show last **suitable acceptance
verification**, not the date a file was read. A dash means no suitable current verification.
Historical dates/results remain in H01/H02. All paths below are repository-relative.
Each page profile plus its capability rows is one joined record: category/module, code,
documentation, test reference and related slice are inherited explicitly by every child ID.
Stable IDs must not be renumbered when new items are added.
